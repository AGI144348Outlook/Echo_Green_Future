## 3. Auditing Protocol

1. Verify the current branch roster and recursive source directory against the audit-skills header. Use pinned commits and reject incomplete/truncated listings. Record added/removed/renamed paths, type changes, inaccessible trees and source drift. Compact membership ranges are exact list representations, not sampling.
2. Resume the represented branch/category's checkpoint. Read **each source file one at a time** in recorded order; retain file/member/within-file positions. Inspect archive members and format-appropriate structured/binary contents, recording inaccessible or uninterpretable material rather than claiming it read. Identical source blobs may reuse an explicit pinned reading with all locations mapped; differing versions need separate attention.
3. Discover MCP-translatable material relevant to that category. Add stable IDs, source repository/branch/commit/path/blob and location, contextual meaning, proposed translation, inputs/outputs/effects, dependencies, conflicts and evidence state to its accumulator. Use cross-references between categories. A discovery, document, card, capability listing or Switchboard entry grants no invocation authority and proves no working runtime.
4. Run the category's 000_CuratorVerification.md: reconcile actual coverage, discoveries and remaining files; refresh the list-only audit header from the current coherent snapshot; preserve old versions in Git. Separate directory verification from content-reading completion.
5. Save checkpoint and follow the README's final explicit directory route. On a bounded stop retain PARTIAL/UNREAD/BLOCKED status and exact resume position; do not restart or fabricate coverage. Branch/category handoffs continue across visits.
