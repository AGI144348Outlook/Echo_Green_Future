## Each existing ChatGPT hourly trigger

1. Read current Contract 000, Dual Order OS Contract000_Audit/REPOSITORIES.json and ROTATION_STATE.json. Deduplicate the scheduled run ID; use an expected-head write when claiming/advancing the cursor. No fresh branch per visit.
2. Select one repository at next_repository_index. Read its main Contract000_Audit/README.md, Curator file, BRANCHES.json and CHECKPOINT.json. Resolve the actual next branch/category/file instead of restarting.
3. Begin the category README with its required directory verification and one-at-a-time file audit. Accumulate only actual contextually read discoveries. Source presence and directory verification do not establish working capabilities or completed reading. Archives/binaries need appropriate readers and explicit coverage limitations.
4. Advance useful Scouts work and, when source-linked records support it, Consolidation/Integration comparative reports. Do not execute code merges, deployments or tests merely because a description exists. Before every test/diagnostic/benchmark/CI publish the hypothesis, method, expectations and falsifiers in the affected repository, and actual results afterward in the same thread.
5. Perform category Curator verification, update the opening list-only mirror and save exact partial coverage. Follow its NEXT route for the local circuit. Preserve outstanding repository cursors across visits.
6. Commit completed maintenance units only under main Contract000_Audit/** using expected-head writes and [skip ci], publish concise evidence/blockers to the existing maintenance issue, and advance the global cursor modulo 20. A blocked repository records its real blockage and yields fairly; a missed run is never invented or flooded with catch-up visits.
