## Why polymath

A polymath intelligence does not specialize.
It holds mathematics, language, logic, science, philosophy, and
structural analysis in one coherent architecture — each discipline
informing the others rather than living in separate modules.

ECHO's two development branches solved the same problem from different
directions. The autonomous-agency branch built the algorithm layer:
the 22 glyph operators, A-000 through A-174, the Recess agent, the
question engine. The algebra branch built the addressing layer: the
Notebook as a persistent resolver, Presentiation semantics, the
query engine, the generalization/specification algebra.

Neither is ECHO alone. Together they are.

## Layer 1: The Registry Layer

### The evolving semantic machine

A conventional registry is: R_static: key → value.

ECHO's registry is:
\`\`\`
ℛ_t = (E, I, M, H, P, C)_t
\`\`\`

- **E** — canonical residents. Each word, formula, glyph, algorithm
  that has been formally indexed. The identity is stable.
- **I** — identity/symbol indexes. Routes from symbol occurrences
  to canonical residents. Not character equality — sense-resolved
  index routes.
- **M** — manifestations. Where a resident appears (in definitions,
  in Pe output, on Canvas, in Recess discoveries).
- **H** — hypernym/semantic structures. The is-a relationships.
  Stored once in the canonical resident, not duplicated per occurrence.
- **P** — Presentiation routes. Routes from occurrences to residents.
  A Presentiation is not a copy.
- **C** — contextual/intersection relations. Where multiple residents
  share a definition, their hypernym neighborhoods intersect.

**Canonical identity is invariant:**
\`\`\`
Identity_t(Rᵢ) = Identity_{t+1}(Rᵢ)
\`\`\`

**Relations evolve:**
\`\`\`
Relations_{t+1}(Rᵢ) ⊇ Relations_t(Rᵢ) ∪ ΔRᵢ
\`\`\`

### Presentiation vs Duplication — the fundamental distinction

Duplication: R → R′ where R′ ≠ R. New canonical identity.

Presentiation: R appears at a new locus. Same canonical identity.
\`\`\`
PRESENTIATE(R, E, p) → Iₖ(R)
Identity(Iₖ(R)) = Identity(R)
\`\`\`

**The correct sequence for dictionary processing:**
\`\`\`
symbol occurrence
  → pattern match (σ(v) found at position o_{d,i})
  → Registry index route established
  → Semantic Presentiation: P(R(v), o_{d,i}) → I(R(v)@o_{d,i})
  → Resident's hypernym neighborhood H(R(v)) accessible at occurrence
\`\`\`

**What this means for Pe:** When Pe speaks a word and the Mirror
checks it, the check should Presentiate the existing lobby resident
at that occurrence — not re-lookup the word as if new. The lobby
already holds the canonical resident. The Mirror should route through
the index, not search again.

### 3.2 Canvas Workspace (algebra branch — designed, not implemented)

\`\`\`

\`\`\`

\`\`\`

## Layer 6: Learning

### Generalization and specification as complementary transformations

Let the invariant topic be T.

\`\`\`
G_T = inclusive/generalizing transformation (remove predicates)
S_T = exclusive/specifying transformation (add predicates)
\`\`\`

The topic identity is preserved under both:
\`\`\`
Topic(G_T(x)) = Topic(S_T(x)) = T
\`\`\`

Predicate delta per step:
\`\`\`
G_n: X_n − ΔPₙ    (generalization removes predicates)
S_n: X_n + ΔPₙ    (specification adds predicates)
\`\`\`

The 22 LHEA operators map to ΔP types:
- FILTER (ד) = remove predicate = generalize
- SEED (י) = add predicate = specify
- BOUND (ח) = add boundary predicate
- INITIALIZE (א) = strip all prior predicates = maximum generalization

The structure is a branching lattice, not a line:
\`\`\`
entity ← organism ← animal ← mammal ← canine ← DOG
                                                    ↙  ↓  ↘
                                         herding hunting working
                                           ↓
                                       border collie
\`\`\`

At every upward movement ask: what did DOG surrender to become more
inclusive?
At every downward movement ask: what constraint was added?

### Inverse-recovery residual

\`\`\`
ε_T = d(T, S(G(T)))
\`\`\`

If ε_T = 0: the semantic round trip recovered the starting state.
If ε_T > 0: the generalization discarded distinguishing information.
This is useful information, not merely failure.

### Adversarial invariant testing

A candidate invariant surviving 3 inversions is interesting.
One surviving 30 independent inversions is substantially stronger.

The inversion family itself grows progressively:
\`\`\`
K₁ →^I₂ K₂ →^I₃ K₃ →^I₄ ...
\`\`\`

VGM submission gate: a candidate must survive N independent
adversarial inversions before it may be proposed for VGM entry.
N is not yet set — requires calibration from Recess data.
