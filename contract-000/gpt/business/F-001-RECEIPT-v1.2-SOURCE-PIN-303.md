## Trust boundaries — required before any parser result can affect a release receipt

1. **Source pin:** The source of truth is the independently selected `The-TAM-protocol` source commit (currently candidate `d46456a18fe412398d0ae37ec5a8c4eebb44e0c9`), a verified per-input blob/sha256 map and the exact `rebuild_datasets.py` blob `fa3a62f76549ecaea6e226ba5cca41597000d790`. A CLI-supplied digest is a comparison value, not an independently authenticated pin. If the verifier cannot obtain a trusted pin from a separately reviewed build record, set `source_pin_authenticated=false`, `source_pin_status=UNVERIFIED`, `release=HOLD`. A commit hash in a repository writable by the same GitHub credential proves content identity, not independent authority.
2. **Dataset A/B:** Compare complete delivered bytes against the independently reconstructed and pinned outputs, not just rows or columns. Current *candidate* hashes from archived prior rebuilds: A `d3c176b9d2ff8041b093f46f28c7b56619d1e1cc3b3ea4841b12027e5ec826f2` (584 bytes, six rows, two editorial flags), B `fecd151b5b7393fc69975a0b323e02c5f306eb1fd49bedc2901f849001e8afc5` (eight rows). Both hashes are **candidate pins**, not authenticated final release artifacts.
3. **Editorial binding:** Pass the *separately obtained* Dataset A expected digest into v5. Read v5's structured `status`, `binding`, `flagged_csv_lines`, `dataset_a_sha256`, `disposition_sha256`, `source_pin_authenticated`, `decision_reference_authenticated` and `release`; never infer success from exit code 0 alone. The only admissible v5 success statuses are `RECORDED_UNAUTHENTICATED` or `NO_FLAGGED_ROWS`, and both remain `release=HOLD`. Require matching dataset and disposition digests in the receipt. The record's `decision_reference` is a pointer, **not** authentication of Timothy's approval. Current flagged CSV lines 6 and 7 require his editorial disposition; synthetic test records are never eligible.
4. **Build provenance:** Preserve the v0 `inputs` map and per-script `git_blobs` for `build.py`, `build_pdf.py`, `rebuild_datasets.py`, `claim_scan.py`, `listing_check.py` and every postprocessor/verifier actually executed. Record `APPLY-ORDER.md` blob, each adopted patch blob and post-patch resulting script hash. Do not claim that any of Claude's proposed patches have been integrated into the shared production build.
5. **Four artifacts:** Exactly `epub`, `pdf`, `dataset_a_csv`, `dataset_b_csv` with independently measured byte count, SHA-256, build record and validation result. EPUB/PDF hashes **null until an actual independently reviewed build**. Validate EPUBCheck/accessibility, PDF layout, claims/listing and rights. Missing artifact or hash → HOLD.
6. **Approval:** `timothy_approval_reference` is null until explicit instruction; `approval_reference_authenticated=false` unless independently witnessed outside the shared push credential. A JSON field `approved:true`, a Git author, a matching digest or a model-generated receipt must never authorize publication.
