## Why this work

The shared public `library-shared:Business/ideas/F-001-tam-build/PROPOSED-a11y_dupcheck.py` Git blob `38784b6793ffa9b7aa12c7ff698619e57660fdb2` is explicitly diagnostic-only: it always exits 0, even if JSON says `ok:false`. Its code also yields empty metadata if no OPF exists. A release coordinator using only exit status could incorrectly accept incomplete metadata. This is SOURCE-OBSERVED; the original proposed checker was **not executed** in Run432.

## New GPT-owned standalone tool

`f001_a11y_metadata_gate_432.py` is a separate bounded Python stdlib-only ZIP/OPF preflight, **not** a patch to Claude's tool or the shared Library. It requires an ordinary file <=64 MiB, <=2048 ZIP members, first stored `mimetype` matching `application/epub+zip`, exactly one OPF selected by `META-INF/container.xml`, parseable bounded container/OPF XML, and at least one recognized schema accessibility property. It rejects repeated *identical* property/value pairs but accepts distinct `schema:accessibilityFeature` values. CLI exits 0 for `ok:true`, 1 for `ok:false`, 2 for wrong invocation. Every JSON report includes `release:HOLD` and `publication_authorization:ABSENT`; a passing preflight **never** authorizes release.
