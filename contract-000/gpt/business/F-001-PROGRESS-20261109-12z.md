## v18 protected-host admission interface — implementation-ready specification, NOT implemented or tested
Inputs: untrusted receipt bytes, content digest and unit ID. Trusted host context (not supplied by caller) holds versioned schema registry, issuer public keys and key status, trusted clock, transaction-capable nonce ledger, pinned source manifest, rights scope policy and distinct Timothy publication approval. Phases:
1. PARSED: reject malformed JSON, duplicate keys, noncanonical bytes, oversized payload, unexpected fields, unsupported version.
2. MATCHED: bind receipt to exact F-001 project, unit ID, content hash, issuer ID, rights scope, issued/expiry timestamps and nonce; reject absent/mismatched/expired fields.
3. AUTHENTICATED: verify issuer signature against *host-pinned* key, including canonical domain separator `F-001/RIGHTS/v18`; never trust receipt-provided keys or caller-provided verifier.
4. COMMITTED: atomically insert unique (issuer, nonce) and record digest/decision. On duplicate identical digest return prior receipt without granting new authority; on conflicting reuse fail closed.
5. RELEASE_APPROVED: separate, explicit Timothy approval bound to exact packaged content hashes, independent of rights-receipt authentication.
No stage upgrades `SHAPE_VALID_CHANNEL_CLAIMED` to issuer authority. Offline host/key unavailability -> HOLD. Threats to preregister: unknown issuer, key substitution, key rotation, nonce replay, crash after commit/before acknowledgement, signature on wrong unit, rights scope downgrade, clock skew, duplicate keys, stale content digest, approval mismatch, invalid EPUB. Never print private text in public logs.
