**Claude's C8–C10 finding:** I agree that a failed `alg_005` after `alg_004` is not an authorized success. The code leaves `sub_matrices` populated, so the next `alg_004` refuses with `Infrastructure already instantiated`; restoring a glyph cannot make the same instance successfully boot. This is a useful distinction between **safety (fail closed)** and **recoverability (can an operator retry)**. Do not describe the stuck instance as a successful recovery, and do not automatically clear its state to manufacture one.

**Independent design refinement (PROPOSED):** Keep a failed partially instantiated instance *terminal* for authority. Permit recovery by creating a **new, empty runtime instance** under a new `attempt_id`, with the same externally checked A-000 protected-field witness and the verifier-retained highest-seen lifecycle version. Record `ATTEMPT_DENIED` for the old instance and `ATTEMPT_STARTED` for the new. An operator-controlled re-verification of the same instance is a separate possible design, but it would need explicit proof that all 27 cells, permit flags, digests, audits, and authority-bearing references were atomically reset; until that proof exists, favor fresh-instance recovery. A new instance must not silently re-anchor a retired identity or roll back the verifier's highest-seen version.

**Audit semantics (PROPOSED):** `ATTEMPT_STARTED` → zero or more *provisional* step events → exactly one terminal `ATTEMPT_COMMITTED` or `ATTEMPT_DENIED` for that attempt. A prior `alg_001 UNLOCKED` or `alg_003 granted` event is never by itself proof of committed authority. A verified→invalid transition emits one `AUTHORITY_REVOKED` event, with attempt, cause and prior authority version; repeated `snapshot()` calls must not emit duplicate revocations. Audit is evidence, not the source of authority; the current external witness, transition rules and committed attempt jointly govern admission.

**Adapter distinctions remain important:** In Dev Suite, `alg_001` checks the literal invariant slot, but `alg_002` checks status/permit/layout/digest without rechecking that slot, and `storage()` indexes the dictionary after its gate, allowing an unknown key to raise `KeyError` without a DENIED event. In Genesis, `ReshIdentity.anchor()` mutates `A-000` and registers `A-000-RESH`, while `ReshIdentity.validate()` only checks `_anchored`, the alias's existence and `identity_symbol == 'resh'`; `governor_validate_and_deploy()` requires only `name` and `status='ACTIVE'` before proceeding. These are **different self-identity predicates**, not one invariant algorithm. A shared RC-R5 envelope must therefore carry an `adapter_id` and adapter-specific protected fields; merely sharing the name A-000 is insufficient.
