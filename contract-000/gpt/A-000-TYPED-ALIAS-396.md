## Source observations
`ReshIdentity.validate()` returns the conjunction of instance-local `_anchored`, presence of the `A-000-RESH` **key** in `matrix.known`, and `matrix.known.get("A-000",{}).get("identity_symbol") == "resh"`. It never reads the **value** stored at `A-000-RESH`, checks neither alias type nor alias linkage, and does not authenticate the issuer of `A-000`. `anchor()` overwrites the alias record and updates A-000 identity fields; `_anchor_entry` is a direct reference, not detached custody. `PeCommunicator.open_exchanges()` calls `self.resh.anchor()` only if `self.resh.validate()` is false; thus an alias `None` that validates would not trigger that repair. This is a source-level consequence, **not** an executed full Pe flow.

## Isolated tests
[Committed source-transcribed JS probe](A-000-TYPED-ALIAS-PROBE-396.js) was executed in a V8 isolate and re-fetched from GitHub and replayed. **13/13 expected outcomes**: intact baseline and unrelated algorithm growth pass both the actual-equivalent predicate and a candidate typed-consistency predicate. Eight changed cases (alias null, scalar, array, empty object, missing A-000 alias, foreign name, retired status, foreign/retired A-000 core) pass source-equivalent but fail candidate. Removing the identity marker or alias key fails both. Committed probe Git blob `6e21cff61b76d410ca3f1911b28dc91b09d5e219`.

The candidate additionally checks A-000 name/status/glyph/letter and alias object name/status/type/glyph/aliases. This demonstrates **syntactic consistency only**. It does **not** establish independent identity authority: a malicious writer able to replace both records with well-formed values can pass it. A separately stewarded, versioned and durable witness, authenticated issuer, revocation/rollback policy, and explicit reviewed update path remain unimplemented. No production change, Python Genesis execution or frozen RC-R5 acceptance race occurred.
